
# CyberMirror API Contract

## Purpose
This document defines how the CyberMirror backend
communicates with the vehicle simulation and dashboard.

## Base URL
http://127.0.0.1:8000

## 1. Create an Alert

- Method: POST
- Endpoint: /api/v1/alerts
- Purpose: Send a detected security alert to the backend.

### Request Body

```json
{
  "timestamp": "2026-10-20T14:00:00Z",
  "severity": "high",
  "attack_type": "CAN_message_spoofing",
  "source": "vehicle_simulation",
  "description": "Suspicious CAN message detected",
  "ecu_id": "ECU_01",
  "risk_score": 85
}
```

## 2. Get All Alerts

- Method: GET
- Endpoint: /api/v1/alerts
- Purpose: Retrieve alerts for the dashboard.

## 3. Get One Alert

- Method: GET
- Endpoint: /api/v1/alerts/{alert_id}
- Purpose: Retrieve a specific alert by its ID.

## Alert Fields

- alert_id: Generated by the backend.
- timestamp: Time the event occurred.
- severity: low, medium, high, or critical.
- attack_type: Type of suspected attack.
- source: System that generated the alert.
- description: Explanation of the event.
- ecu_id: Related electronic control unit.
- risk_score: Risk score from 0 to 100.
- status: Alert status, initially open.

## Notes

- The backend validates incoming alerts.
- Alerts will initially be stored in memory.
- PostgreSQL integration will be added later.
- The final format must be agreed upon by all team members.
